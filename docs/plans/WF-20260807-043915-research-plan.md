## 2. Context (research summary)

Four parallel investigations produced reports in `.opencode/workflows/WF-20260807-043915-research-plan/research/`:
- `01-game-logic-state.md` — Redux match logic, rules, undo, persistence
- `02-routes-ui.md` — app routes, scoring UI, match flow
- `03-auth-data-pwa.md` — Supabase auth, fetchers, PWA/offline
- `04-project-health.md` — tooling, deps, docs consistency
- `00-consolidated.md` — coordinator synthesis + risk ranking

Key verified facts driving this plan:
1. Rematch is broken: `match/finished/page.tsx` redirects to `/` after `rematch()` — user never reaches `/match`.
2. Session middleware is dead code: `src/app/proxy.ts` is in the wrong location (Next.js 16 requires root or `src/` level); no route protection.
3. No `.env*` files locally; dashboard crashes at module scope; login/signup fail without Supabase env vars.
4. Double Out is not enforced: any score landing on 0 wins the leg; only "landing on 1 with double-out" is a bust.
5. BUST button submits `score: 0` → recorded as a non-bust 0-point turn.
6. Client 401-refresh broken: `refreshAccessToken` GETs `/internal/auth/refresh` but the route only exports POST (405).
7. Stats inflated: `NumberPad` always submits `dartsUsed: 3` for non-checkout turns.
8. Roadmap must-haves missing: Resume CTA/logic, full statistics page, guest match history.
9. Docs stale: README/AGENT.md/docs still reference `next-pwa` (migrated to serwist), dev script mismatch, authSlice name wrong.
10. Dead weight: 42/53 shadcn/ui components unused; 9 deps only consumed by them; `date-fns`, `@supabase/supabase-js` unused.

## 3. Scope decisions (validated)

| Decision | Choice | Rationale |
|---|---|---|
| D1 | Fix rematch to land on `/match` with persisted settings | Roadmap intent "rematch with old settings"; current redirect to `/` is a bug |
| D2 | Move session middleware to correct location (root `proxy.ts` or `src/proxy.ts`) | Restores route protection; security-relevant |
| D3 | Keep stub auth path for now, mark for removal in a later cleanup task | No UI calls it; removal is low-risk but out of MVP scope |
| D4 | Double Out enforcement: implement "finish with double" confirmation in FinishConfirmation (no per-dart entry in this phase) | Minimal change; per-dart Throw model is a larger redesign |
| D5 | Guest match history: store locally (localStorage via redux-persist) | No backend write path exists; Supabase sync is Goal 2 |
| D6 | Resume rules: resume only when `status === 'playing'` and a match exists in persisted state | Clear, safe rule |
| D7 | Docs update in same phase | Prevents drift; low risk |
| D8 | Dep cleanup deferred to a dedicated cleanup task (not mixed with feature work) | Keeps feature diffs reviewable |
