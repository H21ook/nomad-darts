# Implementation Plan — WF-20260808-120837-darts-ux-round2

## Goal
Fix 3 darts-app issues reported by the user:
1. **Wizard skip + spurious exit dialog + Mongolian dialog text.** After abandoning a match
   mid-game (X → dialog → Гарах), starting Quick Start again lands directly on the players
   page (step 2) instead of step 1; and the exit dialog appears immediately when starting a
   game from the players page. The exit dialog text is Mongolian while the rest of the app
   is English.
2. **Darts row confusion.** The 1/2/3 "Darts used" row under BUST/Bull/FINISH is always
   visible; selecting 2 records a 2-dart turn, but per X01 rules a normal turn is always
   3 darts — only the final checkout turn can be 1/2/3. User asks how to use it.
3. **Button conditions.** FINISH should be inactive on scores where a 3-dart finish is
   impossible (bogies, >170, 1 with double-out). The FINISH shortcut is already disabled,
   but the exact-score entry path bypasses the check, and straight-out mode at score 1 is
   wrongly disabled.

## Architecture
Client-side fixes in Next.js App Router + Redux. No new deps. Root-cause fixes:
- Wizard step tracked in **local state only** (drop URL-driven `?step=2` init) — kills the
  history-residue bug class.
- Remove the **dummy `pushState`/popstate interceptor** in `match/page.tsx` — it desyncs
  Next.js history and is the only non-user path to the exit dialog.
- `ExitConfirmation` translated to English.
- Darts row shown **only when the score is finishable**; normal turns forced to 3 darts.
- `checkFinishablePoint` made **checkout-mode-aware**; exact-score checkout path guarded.

## Tech Stack
Next.js 16 (App Router), React 19, TypeScript, Redux Toolkit, Tailwind CSS v4, framer-motion, shadcn/ui.

## Global Constraints
- Verify per task: `npx tsc --noEmit`, `pnpm lint`; tests: `npx vitest run src/lib/__tests__/utils.test.ts`
- `pnpm build` at integration verification (after all tasks)
- Dark theme only; tokens zinc + cyan in src/app/globals.css
- Icons from @tabler/icons-react; cn() from src/lib/utils.ts
- Scoring screens: touch-none select-none, onPointerDown for low latency
- UI copy English (app-wide); Mongolian comments stay Mongolian
- N-player safe (no players[0]/players[1] assumptions)
- No new runtime deps; no debug logging; do not commit

### Task 2 — Darts row visibility + mode-aware finishability + guarded checkout path

**Files:** Modify `src/components/scoring/NumberPad.tsx`, `src/lib/utils.ts`;
Modify `src/lib/__tests__/utils.test.ts`

**Interfaces:** `checkFinishablePoint(currentScore, checkout: 'double' | 'straight' = 'double')`.
NumberPad gains `checkout?: 'double' | 'straight'` prop (default 'double').

- [ ] Step 1: `utils.ts` — extend `checkFinishablePoint`:
```ts
export const checkFinishablePoint = (currentScore: number, checkout: 'double' | 'straight' = 'double') => {
  return (
    currentScore <= 170 &&
    currentScore >= (checkout === 'double' ? 2 : 1) &&
    !bogieNumbers.includes(currentScore)
  );
};
```
- [ ] Step 2: `NumberPad.tsx` — add `checkout?: 'double' | 'straight'` prop (default
  'double'); `const canFinish = checkFinishablePoint(currentScore, checkout);`
- [ ] Step 3: `NumberPad.tsx` — wrap the Darts row (lines 156-177) in `{canFinish && (...)}`
  — hidden when the score cannot be finished with 3 darts. Keep label "Darts used".
- [ ] Step 4: `NumberPad.tsx` — in `handleSubmit`, force 3 darts for non-checkout
  submissions: `const darts = finalScore === currentScore ? dartsUsed : 3;` and pass `darts`
  to `onSubmit` (bust path already forces 3). Prevents a stale 1/2 selection leaking into a
  normal turn.
- [ ] Step 5: `NumberPad.tsx` — guard the exact-score path in `handleSubmit`: only open
  `FinishConfirmation` when `finalScore === currentScore && canFinish`; otherwise **block the
  submission** (do NOT submit and do NOT open the dialog for non-finishable scores — a
  normal-turn submit of the exact score would trigger a bogie leg-win at remaining 0).
- [ ] Step 6: `utils.test.ts` — add cases: straight mode score 1 → true; double mode score 1
  → false; straight mode bogie 169 → false; double mode 170 → true.
- [ ] Step 7: Verify: `npx tsc --noEmit`, `pnpm lint`,
  `npx vitest run src/lib/__tests__/utils.test.ts`. Manual: on a non-finishable score the
  row is hidden; on a finishable score it appears; normal turn after selecting 2 records 3
  darts; typing exact bogie score does not open the dialog.
- [ ] Step 8: Report to `.opencode/workflows/WF-20260808-120837-darts-ux-round2/reports/task-2.md`.

### Task 4 (added 2026-08-10, user design review): Remove "Darts used" row; FINISH → dialog

**Files:** Modify `src/components/scoring/NumberPad.tsx` (ownership transfers from T2)

**Rationale:** The 1/2/3 "Darts used" row is redundant — normal turns are always 3 darts,
and `FinishConfirmation` already asks "How many darts did you use to finish?". The row's
only consumer was the FINISH shortcut (direct `onSubmit(currentScore, dartsUsed)`), which
bypassed the dialog's questions. Removing the row also kills the stale 1/2-selection vector.

- [ ] Step 1: Delete the Darts counter row block (`{canFinish && (...)}` with 1/2/3 buttons).
- [ ] Step 2: Remove `dartsUsed` state; `handleActualSubmit` still takes the dialog's count.
- [ ] Step 3: FINISH shortcut: `setShowFinishConfirm(true)` instead of direct
      `onSubmit(currentScore, dartsUsed)` (button already disabled when `!canFinish`).
- [ ] Step 4: `handleSubmit`: `const darts = 3;` for normal turns (exact-score path opens
      dialog when `canFinish`, blocked otherwise — unchanged).
- [ ] Step 5: Verify `npx tsc --noEmit`, `pnpm lint`, `npx vitest run` (45 pass);
      grep "Darts used" in `src/components` → only FinishConfirmation question remains.
      Browser: at 40 → FINISH enabled, NO row; FINISH → dialog asks darts; exact-score
      finishable → dialog; bogie 169 exact → blocked; normal turn always +3 darts.
- [ ] Step 6: Report to `.opencode/workflows/WF-20260808-120837-darts-ux-round2/reports/task-4.md`.
