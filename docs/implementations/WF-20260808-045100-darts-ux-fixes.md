# Research Findings — WF-20260808-045100-darts-ux-fixes

## Issue 1: Quick match skips pages after mid-game exit
- `MatchSetup.tsx` uses `window.history.pushState({step:2}, '', '#order')` (L69) to track wizard step 2, plus popstate listener (L83-101) and a mount effect that calls `history.back()` when `#order` present (L77-81).
- This pollutes the history stack with `#order` entries. Combined with `/match` page's dummy `pushState` (match/page.tsx L38) and `router.replace('/')` on abandon (L64), back/forward navigation can land on `/match/setup#order` where the popstate handler jumps the wizard to step 2 (players page), skipping step 1.
- Persisted `match` slice (store.ts whitelist) + "Resume Match" card (page.tsx L45-59) links directly to `/match` when status is 'playing' — user can land on scoreboard without wizard.
- `abandonMatch` (matchSlice L229-233) sets status 'setup' but leaves players/history intact; `startMatch` overwrites everything (safe).

## Issue 2: Darts row (NumberPad.tsx L150-171)
- Selector for darts used in current turn: 1/2/3 buttons, default 3, cyan when selected.
- Selecting 2 → `dartsUsed: 2` passed to `submitTurn` → `totalDartsThrown += 2` (affects PPR/avg stats). On bust turns dartsUsed is forced to 3.
- On checkout turns the FinishConfirmation dialog re-asks the darts count (ignores the row).
- UI label is just "Darts" — unclear to users.

## Issue 3: Score page header vs AppBar
- match/page.tsx L70-82: custom inline header (h-10, no blur, X icon left, "501 · D/O" text center, spacer right).
- Shared `AppBar` (ui/app-bar.tsx): h-14, sticky, backdrop-blur, back arrow, title, actions slot. Used by MatchSetup, MatchFinished, StatsPage, login, sign-up.
- Fix: use AppBar with `onBack` → exit dialog, `backButtonIcon` = IconX, title = settings text.

## Issue 4: Exit dialog vs checkout dialog
- Exit dialog: shadcn `AlertDialog` (alert-dialog.tsx) — tokens, rounded-xl, z-50.
- Checkout dialog: `FinishConfirmation.tsx` — custom framer-motion overlay, bg-black/80 backdrop-blur-md, bg-zinc-900 rounded-3xl border-white/10, big colored buttons, z-60.
- Fix: restyle exit dialog to match FinishConfirmation design language (or extract shared dialog).

## Bug 5: "Not double" doesn't clear input
- `FinishConfirmation.handleNotDouble` (L19-22) dispatches bust turn + `onCancel()` → only `setShowFinishConfirm(false)`.
- NumberPad local `value`/`displayMode`/`dartsUsed` NOT reset → stale score stays displayed for next player; pressing submit re-opens dialog or submits stale value.
- Fix: cancel handler must clear `value`, `displayMode`, `dartsUsed`.

## Bug 6: Finish button asks Double/Not double
- `handleStrategyClick('FINISH')` sets value = currentScore (L44) → `handleSubmit` sees `finalScore === currentScore` → opens FinishConfirmation (L73-76).
- User wants: FINISH → straight double finish, no question. Use dartsUsed from Darts row (default 3).
- Number-pad exact-score path keeps the dialog (for "Not double" case).

## Issue 7: Undo button color
- NumberPad.tsx L190: `bg-red-500/20 text-red-500 hover:bg-red-500/40` (red).
- Number pad buttons: `bg-zinc-900 border-white/10 text-zinc-400` (FastButton) / SubmitButton base `bg-zinc-900 text-white border-white/5`.
- Fix: neutral zinc style matching number buttons.

## Issue 8: Back from match result page
- `/match/finished` reached via `router.replace('/match/finished')` from match/page.tsx L52.
- Browser back → `/match` → status 'match_finished' → effect L50-54 → replace back to finished → bounce loop (back appears dead).
- AppBar back on finished: `backHref="/"` → `router.push('/')` (push, leaves finished in history).
- Stats page: `backHref="/match/finished"` → push → stack grows.
- Fix: (a) match/page.tsx: on mount with status already 'match_finished' → replace('/'); only redirect to finished when status CHANGES while mounted. (b) finished AppBar back → replace('/'). (c) stats back → replace('/match/finished').

## Issue 9: Stats on match result page
- MatchFinished.tsx: winner-only Average (PPR) L25, Darts, hardcoded "32%" Checkout L158, hardcoded date "24 OCT 2023" L91.
- StatsPage.tsx is the reference: collectLegs (L46-67), buildPlayerStats (L69-122): ppr, dartsThrown, pointsScored, legsWon, setsWon, checkouts, checkoutAttempts, checkoutPct.
- LegTransition.tsx L80-86: per-leg avg + 100+ count.
- Data available: player.totalDartsThrown/totalPointsScored, all leg.turns (history.completedSets + active.currentSet.legs), turn.points/isBust/dartsUsed/remainingScore.
- Computable: PPR, avg darts/leg, avg score/turn, 100+ %, checkout %. NOT computable: per-dart stats (Turn stores only aggregate).
- MatchFinished receives only {id, winner, players} — needs match data (or computed stats) passed from finished/page.tsx.
- Match start date: use first leg startTime or history date.
