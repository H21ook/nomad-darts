## 4. Testability blockers

1. **`matchSlice.ts` line 5: `import { RootState } from "./store"`** — a *value* import of a type-only symbol. Under `isolatedModules: true` TS keeps it, so importing `matchSlice.ts` in a Node test **evaluates `store.ts`**, which:
   - imports `redux-persist` + `redux-persist/lib/storage` — falls back to **noopStorage** in Node (verified in `node_modules/redux-persist/lib/storage/getStorage.js`: `typeof self === 'object'` check → no crash, but logs `console.error("redux-persist failed to create sync storage. falling back to noop storage.")` in non-prod);
   - executes `persistStore(store)` at module load (side effect: starts persistence loop);
   - transitively imports `authSlice` and `matchHistorySlice` (the latter imports `react-redux` hooks).
   - **Verdict:** soft blocker — tests *will run* but with a noisy side effect and unnecessary coupling. **Fix:** replace with a structural type (e.g. `{ match: { snapshots: unknown[] } }`) or `import type` from a types-only module; or type `selectCanUndo` against a local minimal type. Single highest-value refactor for testability.
2. **`nanoid` v5 is ESM-only** — fine for Vitest (native ESM); needs ESM config for Jest. Also `nanoid()` runs at module load in `initialState` (lines 16, 27, 34, 37, 44) → **`initialState` is not a stable constant**; ids are random per import. Tests must not assert exact `id` values.
3. **`@/` path alias** — `redux/utils.ts` line 1 imports `@/types/darts`. Vitest needs `resolve.alias: { "@": <src> }` (or `vite-tsconfig-paths`).
4. **Non-determinism** — `Math.random()` in `startMatch` shuffle (only when `randomOrder: true`) and `getRandomPlayerColor`; `Date.now()` in `turn.timestamp`, `leg.startTime`. Tests: set `randomOrder: false`; assert invariants (order 1..n, all players present) not exact order; use `expect.any(Number)` for timestamps.
5. **No test infrastructure** — no vitest/jest in `devDependencies`, no `test` script in `package.json`, no vitest/jest config, no `*.test.ts`/`*.spec.ts`/`__tests__/` files anywhere. Must be added from scratch.
6. **tsconfig** — `moduleResolution: "bundler"`, `module: "esnext"`, `target: "ES2017"`, `paths: { "@/*": ["./src/*"] }`, no `types` entry. If using Vitest globals, add `"types": ["vitest/globals"]`; explicit `import { describe, it, expect } from "vitest"` is preferred (no tsconfig churn).
7. **Minor:** `submitTurn` default `dartsUsed = 0` (line 129) — ADR-0002 says "defaults to 3 for non-checkout turns", but the slice defaults to 0; the UI always passes `dartsUsed` (NumberPad default state 3, FinishConfirmation passes 3). Test documenting the omitted case (no darts counted) is a real behavior snapshot — flag for coordinator.

## 2. Recommended framework: **Vitest** (v4.x)

### Vitest vs Jest for this project

| Criterion | Vitest 4 | Jest 29/30 |
|---|---|---|
| ESM (nanoid v5 is ESM-only) | Native, zero config | Needs `transformIgnorePatterns` + ESM mode hacks |
| TS via esbuild | Built-in (fast, no babel config) | Needs `babel-jest`/`ts-jest` + `babel.config.js` |
| Path alias `@/*` | `vite-tsconfig-paths` plugin (1 line) | `moduleNameMapper` regex (manual, error-prone) |
| Node 22 support | `engines: ^20 \|\| ^22 \|\| >=24` ✓ | OK |
| pnpm 10 | Works (see §5 risk) | Works |
| Next.js 16 interplay | Independent of `next build --webpack` (own Vite transform) | `next/jest` preset targets Next's SWC; heavier coupling |
| Speed / DX | Watch mode, in-source transform, no cache dirs in repo | Slower, `jest.config` boilerplate |

**Rationale:** The project builds with webpack (`next build --webpack`), but that is irrelevant for unit-testing pure TS modules — Vitest never reads `next.config.ts` and never invokes webpack; it transforms each module with its own esbuild/Vite pipeline. The deciding factors are: (a) `nanoid@5.1.6` is ESM-only and vitest handles ESM natively; (b) `@/*` alias resolution is a one-line plugin; (c) zero babel config needed; (d) Node 22 is an officially supported engine. Jest would require `ts-jest`/`babel-jest`, a `moduleNameMapper` for `@/*`, and ESM transform exceptions — strictly more setup for the same result.

**Verdict: Vitest 4.1.x.**
